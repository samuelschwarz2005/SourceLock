## Why SourceLock exists

Most FiveM leaks are not subtle. A resource arrives as one "cipher" file, rebuilds
its payload from a string, and quietly keeps a Discord webhook or an HTTP endpoint
in its back pocket. By the time it runs, the damage is already done — usually with
your players' data or your server's shell.

SourceLock gives you two layers instead of hope:

| Layer | Question it answers | How |
| --- | --- | --- |
| **Scanner** — `scanner.js` | *Is this resource safe to boot?* | 17 rules, line-level evidence, boot-gate exit codes |
| **Loader** — `SourceLock/` | *Can my client code be skimmed from the cache?* | payload kept out of the manifest, delivered in memory |

Both are small enough to read in one sitting, and neither needs a framework.

## Quick start

```bash
git clone https://github.com/samuelschwarz2005/SourceLock.git
cd SourceLock

# 1. Scan before you boot
node scanner.js ./resources              # exit 0 = clean, 1 = findings, 2 = error

# 2. Optional: report every scan to Discord
export SOURCELOCK_WEBHOOK_URL='https://discord.com/api/webhooks/<id>/<token>'
node scanner.js ./resources

# 3. Optional: run scans from Discord
npm install
DISCORD_TOKEN='...' DISCORD_ALLOWED_ROLE_IDS='123456789012345678' npm run bot
```

### Install the runtime loader

1. Copy `SourceLock/` into your `resources/` folder.
2. Add `ensure SourceLock` to `server.cfg`, after your framework resources.
3. Put your real client code in `SourceLock/client/payload/client_logic.lua`.
4. **Never** list the payload in `client_scripts` or `files {}` — that is the whole point.

## What's new in 1.0.1

This is the first public release, and it ships both halves plus the Discord tooling.

### 📊 Discord reporting

Scan results arrive as a report written for a human, not a grep dump:

- a **headline** that says what happened — *"2 high-risk findings"*, *"3 warnings"*, *"clear"*;
- a **colour** that carries meaning — red = act before booting, amber = review, green = nothing to fix;
- **one card per finding** with **File**, **Why it matters** in plain English, the **Code** line, and the exact `/trust` command;
- a **`➕ N more findings`** card when the list does not fit, and a **`👉 What to do`** section with concrete steps.

URLs are accepted only from Discord hosts, never echoed in logs, and mentions are
disabled so a hostile filename or snippet cannot ping `@everyone`.

### 🤖 The bot

| Command | Effect |
| --- | --- |
| `/scan [path]` | runs the scanner inside `SCAN_ROOT` and replies with the same report |
| `/trust <fingerprint> [note]` | accepts one finding so it stops blocking scans |
| `/untrust <fingerprint>` | removes a trust entry |
| `/trustlist` | lists trusted fingerprints |

The bot fails closed: without `DISCORD_ALLOWED_ROLE_IDS` or `DISCORD_ALLOWED_USER_IDS`
it refuses to start, and everyone else receives an ephemeral denial.

### 🎯 Trust, precisely scoped

Trust is per finding, never per file or rule. Fingerprints are
`sha256(file + rule + normalised snippet)` truncated to 16 hex characters:

- edit that line → new fingerprint, trust no longer applies;
- move the line → trust survives, because line numbers are excluded;
- same text, different rule → still reported.

Trusted findings remain visible as dim `TRUST` rows and in `--json`, but no longer
count towards the summary or the exit code. `--no-trust` ignores the list entirely,
and a corrupt list trusts **nothing** rather than everything.

## Detection rules

| ID | Severity | Detects |
| --- | --- | --- |
| `SL001` | 🔴 high | `loadstring(` |
| `SL002` | 🔴 high | `assert(load(` |
| `SL003` | 🟡 medium | `load(` with dynamic chunks (noisy — verify by hand) |
| `SL004` | 🔴 high | `frombase64(` |
| `SL005` | 🔴 high | `\xNN` hex byte escapes |
| `SL006` | 🔴 high | `\0` / `\123` NUL and decimal byte escapes |
| `SL007` | 🟡 medium | `atob(` / `Buffer.from(..., 'base64')` in JS and NUI |
| `SL008` | 🔴 high | `os.execute(` |
| `SL009` | 🔴 high | `io.popen(` |
| `SL010` | 🔴 high | Discord webhook URLs |
| `SL011` | 🟡 medium | `PerformHttpRequest` / `fetch` with a non-literal URL |
| `SL012` | 🔴 high | `PerformHttpRequest` / `fetch` to a domain outside `ALLOWED_DOMAINS` |
| `SL013` | 🟡 medium | Hard-coded public IPv4 addresses |
| `SL014` | 🔴 high | Compiled Lua bytecode (`.luac`, `\x1bLua` header) — cannot be reviewed |
| `SL015` | 🟡 medium | Binary/NUL bytes inside a source file |
| `SL016` | 🟡 medium | File over `maxFileBytes`, reported instead of pattern-scanned |
| `SL017` | 🟡 medium | File could not be read — check permissions and inspect by hand |

Every hit prints the file, `line:column`, the rule and the offending snippet.
Comment-only lines are skipped, because inert comments cannot execute.

## The loader

```
client/init.lua                      server/main.lua
      │                                    │  readPayload() → cache + hash
      │  playerSpawned (+ settle delay)    │
      │ ─── sourcelock:clientReady ──────▶ │  cooldown + per-minute budget
      │ ◀── sourcelock:challenge ───────── │  single-use token, 10s TTL
      │ ─── challengeResponse(token) ────▶ │  token match + TTL + cooldown
      │ ◀── sourcelock:chunk (×N) ──────── │  24 KB slices
      │ ◀── sourcelock:complete ────────── │  total + expected hash
      │  verify hash → load(..., 't', env) │
      │  pcall(chunk) → running            │
      │ ─── sourcelock:ack ──────────────▶ │  releases the in-flight lock
```

Guarantees the server enforces:

- **Bound to the requester** — the payload only ever goes to the `source` of the request.
- **Single-use tickets** — invalidated the moment they are echoed, whether they match or not.
- **Two rate limits** — minimum gap between challenges, plus per-minute budgets for tickets and responses.
- **Integrity checked** — the client re-hashes the assembled text and refuses anything that is not byte-for-byte what the server read.
- **Text only** — `load(..., 't')`, so no bytecode blob can be smuggled in.
- **One delivery at a time** — the in-flight lock is released only by the client ack.
- **Bounded** — payload size, chunk size, assembly buffer and execution are all capped.

Everything is tunable in `SourceLock/config.lua`, and every value is clamped by
`SourceLock.sanitize()` so a mistyped setting degrades safely instead of hanging the server.

## Security work in this release

Both halves were reviewed adversarially; the fixes below are in the code, not just the README.

| Issue found | Impact if left open | Fix |
| --- | --- | --- |
| A `\0` byte made a source file look binary | one-byte scan bypass | scanned as latin1 **and** reported (`SL015`) |
| Files over `maxFileBytes` skipped silently | pad a backdoor past 2 MB to hide it | reported (`SL016`), never skipped |
| `.luac` bytecode never opened | unreviewable hidden code | flagged (`SL014`) and still pattern-scanned |
| `github.com` / `raw.githubusercontent.com` allowlisted | staged payload fetches exempt | removed from defaults |
| Silent 3-hits-per-rule cap | bury a hit behind decoys | suppressed count printed; `--all` shows everything |
| Unreadable files dropped quietly | locked-down file escapes review | reported (`SL017`) |
| `chunkSize = 0` / `retryDelay = 0` | server hang, client request flood | every tunable clamped |
| `payloadFile` accepted `..` or absolute paths | read outside the resource folder | rejected at startup |
| Unlimited bogus `challengeResponse` spam | free event-handler load | dedicated per-minute budget |
| Payload re-executed after a runtime error | duplicated threads and events | executed at most once |
| 32-bit integrity digest | collisions cheap to forge | two-pass 64-bit FNV-1a |
| Webhook URL could point anywhere | reports leaked to an attacker host | Discord-only endpoints, localhost behind an explicit test flag |
| Hostile filenames could mention `@everyone` | ping spam via a backdoor's name | `allowed_mentions: []`, control characters stripped |
| Any member could run scans or trust findings | one member could whitelist a backdoor | fail-closed allowlist, ephemeral denial |
| `/scan` accepted arbitrary paths | read any folder on the host | resolved and confined to `SCAN_ROOT` |
| Coarse trust (file or rule) | a new backdoor inside a trusted area | per-finding fingerprint including the snippet |

## Honest limits

Nothing here makes client code secret, and the release notes would be dishonest to suggest otherwise.

- **Anything the client runs, the client can read.** Once `load()` fires, your source is in the client's Lua state.
- **The handshake is not authentication.** A modded client can ask for the payload immediately; tickets stop other players and blind spam, not a determined attacker.
- **Static matching finds strings, not intent.** `SL003`, `SL011` and `SL013` need human eyes.
- **Server authority is still mandatory.** Money, items, damage and cooldowns must be validated server-side regardless of what the client claims.
- **Not yet tested on a live server.** The loader was compiled and simulated under Lua 5.4, and Discord delivery was verified, but no FiveM server or live bot gateway was available in this build.
