---

1.0.1 worked but asked you to edit `scanner.js` to change a whitelist. That meant every update of the scanner collided with your local edits, and the diffs were where a quiet exclusion could hide. This release moves those decisions into two small files, one for settings and one for exclusions, and adds the test coverage that should have existed for them.

Everything is backwards compatible. With no config file present the scanner behaves exactly as 1.0.1 did, and `npm test` needs nothing installed.

---

## `.sourcelock.jsonc` — settings, not edits

JSON with comments, trailing commas and a BOM tolerated, because hand-edited configuration should not fail on punctuation.

```jsonc
{
  "targetDir": "./resources",
  "whitelist": ["resources/vendor/"],
  "ignorePatterns": ["**/*.min.js"],
  "rules": { "SL003": "off", "SL013": "medium" },
  "allowedDomains": ["api.myserver.com"],
  "maxFileBytes": 2097152
}
```

New knobs: `targetDir`, `extensions`, `ignoreFile`, `ignorePatterns`, `rules`, plus every value that used to require editing the `DEFAULTS` block — all of them range-checked.

`targetDir` resolves relative to **the config file**, not the shell's working directory, so a committed config produces the same scan wherever it is invoked from.

### Typo-proof, on purpose

An unknown key, a wrong type, an out-of-range number or an unknown rule ID stops the scan with exit code `2`. A misspelled `"ignorePrivateIPs"` must not quietly leave a check running that you believe is off — or the reverse. `__proto__`, `constructor` and `prototype` are rejected outright.

The opposite applies to the ignore file: an untrustworthy pattern (`..`, an absolute path, control characters) is skipped **with a warning** and the scan continues. Aborting a whole audit over one bad line is the worse failure.

## `.sourcelockignore` — gitignore semantics

```
# vendor bundles are reviewed elsewhere
vendor/

# compiled assets
**/*.min.js
!critical.min.js

/bootstrap.lua
```

`*`, `**`, `?`, a leading `/` to anchor at the scan root, a trailing `/` for directories only, and `!` to re-include. Matching is case-insensitive and the last matching rule wins. When any `!` rule exists, ignored directories are still traversed — pruning them would make re-inclusion impossible.

**Built for hostile patterns.** Matching is a two-pointer segment matcher plus dynamic programming for `**`; no user glob ever reaches the regex compiler, so `*a*a*a*a*a*a*a*a*` costs linear time instead of backtracking forever. Whitelist entries, which do use wildcards, are capped at four. Both files are capped at 256 KB, 2000 patterns and 200 characters per pattern.

`--config`, `--ignore` and `--no-config` are there for CI: `--no-config` ignores both files when you want a scan that provably used the shipped defaults.

## Fixed: `followSymlinks` did nothing

Found by the new tests, and only by them. A `Dirent` for a symlink reports `isDirectory()` and `isFile()` as `false`, so the scanner's file check dropped every link even with the option enabled — the setting looked supported and was not.

Entries are now `stat`'ed, links resolve, and a `realpath` visited set keeps self-referential links from recursing until the stack dies. It stays **off** by default: following links can walk outside the tree you intended to audit.

Two smaller bugs fell out of the same work: `SL011`–`SL017` were missing from the rule table, so `rules: { "SL013": "off" }` was rejected as an unknown rule, and a UTF-8 BOM silently became part of the first ignore pattern, disabling that exclusion on the Windows editor that wrote it.

## Verification

The suite grew from 35 checks to **60**, all passing on Node 18+, with no dependencies:

| Suite | Checks | Focus |
| --- | --- | --- |
| Config parsing and precedence | 21 | JSONC, validation, merge order |
| Config edge cases | 12 | `--config`/`--ignore`/`--no-config` interplay, rule downgrading, ignore negation |
| Adversarial round 1 | 14 | escapes, oversized files, hostile paths, report content |
| Adversarial round 2 | 13 | symlinks and loops, limits, pathological globs |

The test helpers clear `SOURCELOCK_WEBHOOK_URL` for every spawned scan, so a developer machine configured for a live channel cannot post reports about synthetic findings. Several earlier runs during development did exactly that, which is how the gap was noticed.

## Upgrading

Nothing to do. No config file → identical behaviour to 1.0.1. To adopt the new files:

```bash
cp .sourcelock.example.jsonc .sourcelock.jsonc   # then delete what you do not need
node scanner.js ./resources
```

---

## Still true

- Detection is string matching, not intent. `SL003`, `SL011` and `SL013` need human eyes.
- Every whitelist and ignore entry is a place the scanner will never look.
- The loader raises the cost of dumping client code; it does not make it secret.
- No live FiveM server or bot gateway was available for this build — the loader is compiled and simulated, not field-tested.
